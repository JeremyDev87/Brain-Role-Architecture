# Contributing

1. Discuss contract changes before implementation, especially P0 semantics.
2. Use synthetic PUBLIC fixtures only.
3. Add a requirement ID and conformance coverage for every normative change.
4. Run `make verify` and report exact results.
5. Keep commit, push, release, deployment, and visibility changes behind maintainer approval.

P0 semantic changes require a new architecture identity and specification major version; they are not
normal in-place patches.
